# ADR-20 播报音质：文本归一化、MiMo 云 TTS 与 ZipVoice 本地复刻

> 对应功能：降低机械感、可选云音色、可选本地参考录音音色。承接 [ADR-19](./ADR-19-local-ai-tts.md)。

## 背景

ADR-19 解决了"只有善怡一个音色"和"本地引擎不可用"的问题，但用户仍反馈音色生硬、
断句机械。调研报告列出多条候选，按仓库的本地优先边界分成四档：

- P0：不出网即可改善——自动音色优先级、默认语速与文案标点。
- P1：只在播报路径做文本归一化。
- P2：显式开启的云 TTS（小米 MiMo）。
- P3：本地零样本音色（ZipVoice）。

## 决策

1. **P0 音色与文案**：系统原生自动优先级改为普通话增强款优先（Shelley/Sandy/Reed/
   Rocko/Eddy/Flo），其次婷婷普通话，粤语善怡排最后；英文音色仍只能手动选择。
   默认语速保持 1.0×，不改变用户既有听感；默认播报模板补足逗号，避免合成器把
   整句连读。自动音色变化只影响未保存或失效的 profile，用户已保存的合法音色不被
   覆盖。
2. **P1 播报文本归一化**：新增 `normalizeForSpeech`，只在交给 TTS 前处理四类确定性
   写法——时间 `12:30 → 12 点 30 分`、百分比 `45% → 百分之 45`、版本号
   `v1.2.3 → 版本 1.2.3`、容量/耗时 `1.5GB → 1.5 吉字节`。不改看板、通知、数据库
   或规则文案；不替英文品牌名音译。函数幂等，空转与重复调用安全。
3. **P2 云 TTS 实现为 MiMo 后端，但默认关闭**：`voice.backend = 'cloud'` 时，
   只有 `cloudEnabled = true` 且填写了 `cloudApiKey` 才发请求；endpoint、model、
   voice 均可在设置覆盖，留空用 MiMo 官方默认值。请求超时 30 秒，HTTP 错误体截断
   到 300 字展示，不记录请求正文或 Key。失败只报错，不回落系统音色——与 ADR-19 的
   "不静默换音色"一致。Key 只存本机 `settings.json`，不写入仓库、审计或日志。
4. **P3 ZipVoice 作为第二个本地引擎**：`voice.localEngine = 'zipvoice'` 时使用
   `sherpa-onnx-zipvoice-distill-int8-zh-en-emilia`。模型包不自带声码器与英文词典，
   模型管理器追加两个直接下载文件（`vocos_24khz.onnx`、`lexicon-en-us.txt`），
   总大小约 162MB，仍只在用户点击后出网。ZipVoice 没有预置发音人：每次合成用
   `voice.zipvoiceReferencePath` 的 WAV 与逐字对应的
   `voice.zipvoiceReferenceText`，`num_steps = 4`，并设置
   `min_char_in_sentence = 10`。参考音频由主进程的文件选择器复制到
   `userData/voice-references/`，限制 WAV、≤20MB；用户原文件可移动或删除。
5. **模型管理泛化为规格表**：`LocalModelManager` 接受 `ModelSpec`，保留
   `KokoroModelManager` 兼容旧调用；状态与 `model.progress` 事件带 `kind`，
   `GET/POST /api/v1/voice/model*` 用 `kind` 选择模型，旧客户端不传时默认 Kokoro。
   两套模型可独立下载、取消与就位，互不覆盖。
6. **不新增自动降级**：云、Kokoro、ZipVoice 都是一条单后端链。缺 Key、缺模型、
   缺参考音频、运行时缺失或播放失败时返回具体原因，由通知/试听区展示。

## 影响

- **未实测的云接口**：MiMo 的 endpoint、模型名、音频字段来自公开文档与调研报告，
  本轮没有可用 Key，未发真实请求；协议变化时只需改 core 的默认常量与解析函数。
- **未实测的 ZipVoice 音质**：模型配置与参数取自上游 sherpa-onnx C++ 示例，原生
  运行时路径通过单测桩验证；真实模型下的中文/英文音质、参考音频时长与采样率兼容性
  需用户实际试听。上游自带示例音频是真人声音，不能随应用分发。
- **参考音频缓存**：引擎按文件路径缓存解码后的波形；通过应用内选择器更换录音会写入
  新文件名，因此不会读到旧缓存。若用户在外部原地替换同名文件，需重启应用生效。
- **云 TTS 出网**：开启后播报文本会离开本机，这是本功能唯一的运行期出网例外；
  设置页与隐私文档均已明示，关闭开关后不再请求。
- **文本归一化的边界**：只覆盖四类高确定形态；"1:2" 比例、URL、代码标识符保持原样。
  英文缩写与品牌名交给引擎按原文读，避免误读。
- **ZipVoice 无预置音色**：未选择参考音频时试听直接报错，不退回 Kokoro，避免用户以为
  听到的是自己选择的音色。

## 回滚成本

低。云后端删除 `tts-chain.ts` 的 cloud 分支即回到原生；本地引擎把
`localEngine` 固定为 `kokoro` 并隐藏 ZipVoice 选项即可；文本归一化是独立纯函数，
不调用即恢复原文播报。
