# 知识同步

## 输入

- 刚完成的实现变化（包、进程、API、适配器、验证命令）
- 受影响的知识页（默认 `architecture` / `constraints` / `verification`）

## 步骤

1. 读现有 `.agents/knowledge/*.md` 与对应源文件，确认哪些句子不再真实。
2. 只更新变化的段落。保持结构：适用范围 → 来源路径 → 当前实现 → 待确认 → 更新触发。
3. 新约束写入 `.agents/rules/` 对应主题，不要把长规则复制进知识页。
4. 核对相对链接：知识页链到 `docs/`、`packages/`、`tests/` 的路径仍有效。
5. 不写入本次运行的测试输出、宿主名称、或「已验证通过」快照。

## 暂停

- 变化尚未合入源码，只有口头计划。
- 需要改 `AGENTS.md` 阅读路由以外的业务代码。

## 输出

- 更新了哪些知识/规则文件
- 仍然过时、但证据不足故未改的条目
