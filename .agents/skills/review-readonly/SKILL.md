# 只读审查

## 输入

- 审查目标（文件范围、diff、模块、或 FR/TODO 编号）
- 审查问题（正确性、安全、文档一致性、测试缺口等）

## 步骤

1. 只读。不改业务代码、配置、或 git 状态。
2. 先读批准范围内的源文件，再对照 `docs/` 与 `.agents/knowledge/`。文档与代码冲突时，**以源码为当前事实**，把文档偏差列为发现，而不是自动改文档。
3. 检查：非法状态迁移、core 工具名泄漏、扫描路径越界、控制 API 鉴权、渲染层是否引入打包器、测试是否覆盖新行为。
4. 按 [review-handoff.md](../../templates/review-handoff.md) 输出。区分缺陷、风险、文档过时、超出范围的建议。

## 暂停

- 没有可读的 diff 或文件范围，且猜测会误导。
- 审查结论依赖运行时而本地无法复现：标明未验证，不编造通过。

## 输出

填写 [review-handoff.md](../../templates/review-handoff.md)。结论先于细节。不附带直接修复，除非用户另行授权实施。
